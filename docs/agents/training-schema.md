## Purpose

Corrections, coach notes, and simulator outcomes share one append-only event log. Later exporters read that log. Import the types from `contracts/training.py`. Do not define a second TrainingEvent. Ontology, the gateway, S1/S2 routing, the Decision Router, the policies API, and the Mubit-only rule are unchanged.

## Key files

- `contracts/training.py` — `TrainingEvent`, `InputRef`, `S1Label`, `S2Action`, `SaplingVerdict`, `content_hash_for`, `adapt_correction`.
- `contracts/models.py` — `Correction` v1 fields. The memory shape. Older rows still load.
- `contracts/schemas/` — JSON Schemas, including `TrainingEvent.json`. Regenerated by `python -m contracts.export_schemas`.
- `training/log.py` — append-only writer. Dedup on `content_hash`. No edit and no delete.
- `training/events/events.jsonl` — default log. `TRAINING_EVENTS_PATH` overrides it. `*.jsonl` here is gitignored.
- `api/routes/endpoints.py` — `CorrectionIn` accepts the legacy body and the v1 fields, then the adapter.
- `eval/correction_loop.py` — still writes `corrections.jsonl` and `sft.jsonl`, and appends one event.

## Interfaces/contracts

`TrainingEvent` is one JSON object, Pydantic v2, `extra=forbid`. `schema_version` is `1`.

| Field | Rule |
|---|---|
| `event_id` | UUID. Filled when omitted. |
| `created_at` | UTC. A naive datetime is read as UTC. |
| `task` | `s1_triage`, `s2_action`, or `sapling_verdict` |
| `group_id` | Same call across Thai, English, and paraphrases. Splits use this. |
| `input_ref` | `case_id`, `turn_ids`, `lang` (`th`, `en`, `mixed`), `policy_ids`, `memory_ref` |
| `output_model` | Closed label for `task`, or null |
| `output_correct` | Closed label for `task` |
| `reason` | Non-empty |
| `source` | `human`, `coach`, or `sim` |
| `corrected_by` | `operator`, `supervisor`, or `caseworker`. Required when `source` is `human`. |
| `weight` | Default human `1.0`, coach `0.5`, sim `0.25`. An explicit value wins, then a table passed to `adapt_correction`, then `TRAINING_WEIGHT_HUMAN` / `_COACH` / `_SIM`. |
| `model_version` | Non-empty, for example `s1@v3` |
| `policy_version` | Policies API corpus pin |
| `content_hash` | SHA-256 hex of `task` + `input_ref` + `output_correct`. Filled by the model. A wrong caller-supplied hash is rejected. |

Closed enums live in `contracts/training.py`:

- `s1_triage` — `S1Label`. Values are the policies API label ids.
- `s2_action` — `S2Action`. Values are `RouterDecision.next_action` (`NextAction`).
- `sapling_verdict` — `SaplingVerdict`: `supported`, `violation`, `missing`, `contradicted`, `unsure`. This is the label. `system2.sapling_client.SaplingVerdict` is the runtime result and is a different type.

`content_hash_for` is the only hash. UTF-8 JSON of `{task, input_ref, output_correct}` with sorted keys and separators `( ",", ":" )`. Weight, reason, source, and event id are not in the hash.

`Correction` v1 fields, all optional: `schema_version`, `task`, `group_id`, `turn_ids`, `lang`, `policy_ids`, `memory_ref`, `output_model`, `output_correct`, `source`, `weight`, `model_version`, `policy_version`. `field`, `old_value`, and `new_value` stay the memory record.

`adapt_correction` copies a `Correction` into a `TrainingEvent`. `source` defaults to `human`. Task is the v1 field, or it is inferred from `field`:

| `field` | task |
|---|---|
| `s1_triage`, `s1`, `s1_label`, `label`, `triage`, `priority`, `route` | `s1_triage` |
| `s2_action`, `s2`, `action`, `next_action` | `s2_action` |
| `sapling_verdict`, `sapling`, `verdict` | `sapling_verdict` |

`output_correct` is the v1 field, otherwise `new_value`. A legacy `old_value` is kept only when it is already a closed label. `group_id` defaults to `case_id`. `lang` defaults to `en`. `model_version` defaults to `legacy@unversioned`. `policy_version` defaults to the current policies API pin. A priority or a route is not a label. Those rows raise `AdaptError` and stay on `corrections.jsonl`.

`POST /cases/{case_id}/corrections` still stores a legacy correction and returns 200. If the body set any v1 field and the adapter raises, the route returns 422 and writes no event.

`append_event` appends under an exclusive lock. It does not rewrite earlier lines. A repeated `content_hash` is skipped (`AppendResult.written` is false).

The correction loop's event for `CORR-LOOP-1` is `s1_triage`, `output_model` null, `output_correct` `sphere_water_short`, `source` `human`, `model_version` `s1@stub-0`. The route names stay on the memory row and in `sft.jsonl`.

`GET /training` (`api/routes/training.py`) counts this log by `task` and `source`, lists the export manifests, and joins the fine-tune registry with each version's `metrics.json` (loss curves). `/ui/training.html` draws it. See `docs/agents/training-surface.md`.

Export shapes from the event log are s1 `{text, label, group_id, weight}`, s2 chat to an action plus a short reason, sapling `{policy, evidence, claim, verdict}`, and prefs `{prompt, chosen, rejected}` where `output_model` differs from `output_correct`. Each export writes a manifest (`schema_version`, event count, `policy_version`, hash). Exporters dedup on `content_hash` and do not edit the log.

`make export-training` reads that log. `SYNTHETIC=1` also writes SetFit rows from `fixtures/synthetic`: `training/out/s1_synthetic.jsonl` (train groups) and `s1_synthetic_heldout.jsonl`. The row is `{text, label, group_id, weight}`. `label` is the call's primary label. The original 24 fixtures stay on the log export.

`make export-laya` writes `training/out/laya/train.jsonl` and `held.jsonl` from the same group split. This is the laya 0.4.14 JSONL schema, not a TrainingEvent. Each line is `{state, questions, expected}`. `state` is `{"body": "<speaker>: <text>"}` because every question names the field ``body``. `priority` is a `choice` over `red`, `yellow`, `green`, `white`, `black`. Each other label in `policies/system1_labels.yaml` is a `noul` question whose `expected` value is `true` or `false`. `language` and `tags` are optional slice fields the trainer ignores. The command that consumes the files is `laya-train --data training/out/laya/train.jsonl --eval training/out/laya/held.jsonl --base convaiinnovations/laya-multilingual --out training/out/laya-ckpt`. `make laya-train` runs that only when `LAYA_TRAIN=1` and a GPU or a Modal task is present. Otherwise it prints `skipped`.

## Invariants

- One schema. Other agents import `contracts.training`. A schema change is a proposal in this file, not an edit to the contract.
- The log is append-only. Dedup skips a line. It does not delete one.
- `schema_version` stays `1` until a proposal is accepted.
- Human events require `corrected_by`. Coach and sim may omit it.
- Decisions in `config/decisions.yaml` stay `TODO_HUMAN`. This log does not promote a rule into System 1.
- Model calls stay on the Mubit path. The adapter reads the local policies API for the corpus pin. It does not call Mubit.
- Synthetic cases only. Do not put a phone number, a national id, or a secret in an event.
- `sim/coach.py` still writes `eval/out/coach.jsonl` with `source=coach`. Those rows are not `TrainingEvent`s yet.

## Common pitfalls

- Copying the enum into another module. Import `S1Label`, `S2Action`, and `SaplingVerdict`.
- Treating `welfare_distribution` or `P1` as an s1 label. They are not in `S1Label`. The adapter will not invent one.
- Opening the JSONL in write mode. `append_event` is the writer.
- Hashing a different field set. Use `content_hash_for`.
- Confusing the Sapling label enum with `system2.sapling_client.SaplingVerdict`.
- Editing `contracts/training.py` from an exporter, eval, or UI task. Write the proposal below.
